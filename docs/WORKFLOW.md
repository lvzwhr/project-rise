# 怎么查看、沟通、监控、验收这三人

你面对的是**一个制作人对话**，不是三个独立聊天窗口。设计师、程序员、美术是子代理：制作人把任务派给他们，他们在隔离上下文里干活，再把结果交回这个对话和仓库文件。

## 1. 在哪查看这三个人

| 看什么 | 去哪 |
| --- | --- |
| 角色设定（人设、职责、禁区） | `.cursor/agents/combat-designer.md` 等三个文件 |
| 分工和并行规则 | `docs/TEAM.md` |
| 聊天里能不能点到他们 | Agent 输入框输入 `/`，应能看到 `/combat-designer`、`/combat-programmer`、`/combat-artist`、`/kickoff` |
| Cursor 设置里的子代理列表 | Customize / Agents（或 Cursor Settings 里的 Subagents），项目级来自 `.cursor/agents/` |

刚加完文件时，若 `/` 菜单还没有这三个人，**新开一个 Agent 聊天**（旧会话可能还没刷新名单）。

他们不是 Slack 频道，不能各自挂着等你私聊。每次出场都是一次任务。

## 2. 怎么沟通

推荐：跟制作人说人话，由他分派。

```text
让设计师出最小可玩招式表
让程序按招式表搭状态机和 Debug HUD
让美术先出预警色和翻滚时间轴
设计师和美术先并行，程序等事件名冻结
```

点名召唤（跳过制作人判断，仍在当前对话里开一张子代理卡片）：

```text
/combat-designer 只写玩家轻击和翻滚，60FPS 帧数
/combat-programmer 接上 i-frame，并打开 hitbox 线框
/combat-artist 把敌人砸地的预警拉到至少 20 帧
```

`/kickoff` 会按固定顺序启动第一轮：先设计，再程序+美术并行。

给任务时尽量写清：**要什么文件、验收什么、不要做什么**。子代理看不到你和制作人之前的闲聊，除非制作人把上下文写进任务。

同一条线要续做，对制作人说「让设计师接着改架势表」；需要带着上次记忆续跑时，说「resume 刚才那个设计师」。

## 3. 怎么监控进行中的工作

子代理一启动，当前对话里会出现 **Task 卡片**（名字就是设计师/程序/美术）。

- 卡片展开：能看到他们读了哪些文件、改了什么
- 编辑器：左边文件树和 diff 就是他们的工作区
- 并行时会有多张卡片同时跑

看产物比看聊天更准：

| 角色 | 先看这些 |
| --- | --- |
| 设计师 | `docs/design/`（GDD、招式表、敌人、手感目标、验收清单） |
| 程序员 | `game/`、`docs/engineering/` |
| 美术 | `docs/art/`、`game/assets/` |

程序是否真的能玩：用本机编辑器打开项目

`D:\godot\Godot_v4.7.2-stable_win64.exe`

## 4. 怎么验收

以 `docs/design/acceptance.md` 为准（第一轮由设计师写）。每一条必须是你能在竞技场里做出来的动作，而不是形容词。

建议顺序：

1. 设计师交表 → 你扫一遍范围，有没有偷加养成/开放世界
2. 程序交场景 → 你进 Godot 按验收清单点一遍，开 Debug HUD
3. 美术交时间轴 → 你看预警红、判定黄、破绽是否一眼能懂
4. 失败项写回制作人，例如：「翻滚无敌太长，让设计师把 i-frame 从 13 收到 10，程序对齐」

通过 = 你亲自打过，且 Debug 能看见对应状态。不要只听子代理说「已完成」。

## 5. 你不需要做的事

- 不用给三个人分别开三个 Cursor 窗口（除非你想自己当制作人，同时开三个 Agent 聊天并手动对齐仓库）
- 不用在子代理卡片里逐条回复工具调用；有意见跟制作人说即可
- 文件冲突时让制作人串行，或明确要求「各自在隔离 worktree 里做，做完再合并」
