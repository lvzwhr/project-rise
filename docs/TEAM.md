# Rise Combat Team

制作人（当前对话里的主 Agent）只做分派、对齐和验收。设计、程序、美术分别由三个子代理完成。

## 成员

| 子代理 | 职责 | 不做什么 |
| --- | --- | --- |
| `combat-designer` | 战斗规则、招式表、敌人行为、手感目标、验收标准 | 不写战斗代码，不画最终资源 |
| `combat-programmer` | Godot 战斗框架、状态机、判定、输入、Debug HUD | 不定数值，不改视觉风格 |
| `combat-artist` | 可读性、占位模型、动画时间轴、预警色、受击/挥砍特效 | 不写系统设计，不改判定逻辑 |

调用方式：在对话里直接说「让设计师出招式表」「让程序搭状态机」「让美术出预警规范」，或写 `/kickoff` 启动第一轮。完整操作说明见 `docs/WORKFLOW.md`。

## 默认工作流

1. **设计师**先出最小可玩规格：玩家动作、体力/架势、一名敌人、验收清单
2. **程序**和**美术**并行：程序搭框架和 Debug，美术出占位体与动画时间轴
3. **设计师**对照手感目标验收；不合格就改数据，不要先加系统
4. 只在现有系统仍验证不了「法环感」时，才加下一个系统

## 并行规则

- 设计规格未冻结前：只跑设计师
- 招式表和动画事件名冻结后：程序与美术必须并行
- 改判定、体力、无敌帧：设计师出数，程序改，美术只在时间轴对不上时介入

## 手感冻结线

第一版只验证这些，不扩系统：

- 攻击三段：起手、判定、后摇
- 体力：攻击 / 翻滚 / 格挡共用
- 翻滚无敌帧
- 锁定
- 轻击 / 重击 / 蓄力重击 / 跳跃攻击
- 格挡与架势击破
- 部分重击有超级装甲
- 敌人攻击有清晰预警
